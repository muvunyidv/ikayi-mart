1. WHAT THIS PRODUCT IS
===============================================================================

IKAYI MART is a Flutter multi-platform marketplace prototype (package name
ikayi_mart, version 1.0.0+1) for Rwanda.

Two experiences live in ONE app, switched by NavigationState.mode (NOT by URLs):

  1) Shopper / storefront
     Guest catalog, product detail, guest checkout, fake tracking ID.
     No account. No login.

  2) Vendor Central
     Dashboard KPIs, inventory CRUD (local only), order status board,
     placeholder BMS Sync + Support screens.

There is NO backend, NO auth, NO persistence, NO named routing, NO HTTP client.
Everything is in-memory mock data + Provider.

Intended platforms (from .metadata): Android, iOS, macOS, web, Windows.
There is NO linux/ folder. Web is the real deployment target (GitHub Pages).

Live/custom domain: mart.ikayi.app
Design comments in code reference a "Stitch design system" plus brand orange.

Marketing copy (web/index.html and web/manifest.json):
  "Fast, 3-step guest checkout e-commerce marketplace and vendor management
   platform in Rwanda."

The UI currently behaves more like 2 steps (browse → checkout).
Checkout heading says "CHECKOUT — Step 2 of 2".

Copy and data are Rwanda-specific: RWF, Kigali districts/sectors,
MTN MoMo / Airtel Money, 60-minute Kigali delivery messaging,
Imigongo geometric motif.

README.md is still the default Flutter template. Ignore it for product intent.

4. APP BOOTSTRAP AND NAVIGATION ARCHITECTURE
===============================================================================

main() {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(const IkayiMartApp());
}

IkayiMartApp (StatelessWidget):
  MultiProvider:
    ChangeNotifierProvider(create: (_) => CartState())
    ChangeNotifierProvider(create: (_) => NavigationState())
  MaterialApp:
    title: 'IKAYI MART | E-Commerce & Business Marketplace'
    debugShowCheckedModeBanner: false
    theme: AppTheme.light          // LIGHT ONLY — no dark theme
    navigatorObservers: [ScrollToTopObserver()]
    home: const AppShell()         // NO routes map, NO onGenerateRoute

MODE SWITCH (AppShell watches NavigationState.mode):
  if nav.mode == AppMode.shopper
    → LandingScreen(key: ValueKey('mode-shopper'))
  else
    → VendorShell(key: ValueKey('mode-vendor'))

The ValueKeys remount the tree on mode switch so scroll starts at top.

SHOPPER SUB-PAGES use imperative Navigator.push(MaterialPageRoute(...)):
  Landing → ProductDetailScreen(productId: product.id)
  Landing cart icon / PDP cart / PDP Buy Now → CheckoutScreen
  PDP recommended card → another ProductDetailScreen (STACK GROWS; Back pops one PDP)

VENDOR SUB-PAGES are NOT routes.
  VendorShell switches on nav.vendorSection and wraps body in:
    KeyedSubtree(key: ValueKey(nav.vendorSection), child: body)

SCROLL-TO-TOP:
  ScrollToTopObserver jumps PrimaryScrollController on didPush / didPop / didReplace.
  Landing uses a PRIVATE ScrollController, so the observer often does NOTHING there.
  Landing also calls _scrollToTop() (jumpTo(0), not animate) before opening PDP,
  checkout, or vendor mode.

How shopper enters vendor: header IconButton storefront_outlined → nav.setMode(AppMode.vendor)
How vendor returns to shop:
  Desktop: "Back to Storefront" TextButton.icon
  Mobile AppBar: TextButton "Shop"
  Both call setMode(AppMode.shopper)

NO deep links. NO browser URL changes for screens (Flutter web default).

class Product {
  required: id, name, category, priceRwf (int), imageUrl, vendorName,
            description, stock
  optional: badge (String?), originLabel (String?),
            gallery (default const []),
            variants (default const []),
            isActive (default true)
  defaults:
    deliveryNote =
      'Fast Kigali delivery — most orders arrive within 60 minutes in Gasabo, Kicukiro & Nyarugenge.'
    warrantyNote =
      'Seller-backed warranty. Chat support available for returns & exchanges.'

  bool get isLowStock => stock > 0 && stock <= 5;
  bool get inStock => stock > 0;
  List<String> get allImages =>
      gallery.isEmpty ? [imageUrl] : [imageUrl, ...gallery];
      // gallery is EXTRA shots; imageUrl is always first

  NO copyWith on Product. Inventory edit reconstructs Product(...) fully.
}

class CartItem {
  final Product product;
  final int quantity;                        // default 1
  final Map<String, String> selectedVariants; // default const {}
  int get lineTotal => product.priceRwf * quantity;
  HAS copyWith.
}

enum OrderStatus { pending, processing, shipped, delivered, issueReported }

extension OrderStatusLabel on OrderStatus {
  pending        → 'Pending'
  processing     → 'Processing'
  shipped        → 'Shipped'
  delivered      → 'Delivered'
  issueReported  → 'Issue Reported'
}

class OrderLineItem {
  productName, quantity, unitPriceRwf
  int get totalRwf => unitPriceRwf * quantity
  NO product id — names only.
}

class CustomerOrder {
  required: id, guestName, phone, district, sector, landmark, items,
            deliveryFeeRwf, status, createdAt
  optional: paymentMethod (default 'MTN MoMo'),
            supportTicket (String?)
  int get itemsTotalRwf
  int get grandTotalRwf => itemsTotalRwf + deliveryFeeRwf
  String get locationLabel => '$sector, $district'
  NO copyWith. Status changes rebuild the whole object field-by-field.
}

----- ImigongoBackground (UNCOMMITTED REWRITE) -----
lib/core/widgets/imigongo_background.dart

Rwandan Imigongo-inspired zigzag/diamond mesh. CustomPainter only — no assets.
Comment: Flutter equivalent of an inline SVG data:image/svg+xml CSS background.
Matches IKAYI BMS motif: continuous horizontal zigzag/chevron strokes stacked so
peaks of one row meet valleys of the next → seamless diamond mesh. Nested
parallel zigzags add inner-diamond imprint.

enum ImigongoVariant { dark, light, navActive }

Constructor:
  required child
  variant = ImigongoVariant.light
  backgroundColor (optional override)
  patternOpacity (optional override)

Resolved backgrounds:
  dark      → AppColors.inverseSurface
  light     → AppColors.surfaceBackground
  navActive → AppColors.primaryLight

Resolved opacities (CHANGED in uncommitted work):
  dark      → 0.10   (was 0.09)
  light     → 0.85   (was 0.07)  // "soft watermark: light grey stroke already near the ground color"
  navActive → 0.18

Stroke colors:
  dark      → Colors.white
  light     → Color(0xFFE2E8F0)  // was AppColors.onSurface; "matches reference soft grey"
  navActive → AppColors.primaryOrange

Painter constants (NEW):
  _periodX = 40   // peak-to-peak horizontal wavelength (BMS ~36–40px tile)
  _periodY = 40   // full diamond height
  _nest    = 5    // inset for nested inner diamond outline

Light/dark paint (_paintChevronMesh):
  Main stroke width 1.2, StrokeJoin.miter, StrokeCap.butt
  Nested stroke width 1, alpha * 0.85
  Rows every halfY (20px) so valleys sit on next row's peaks
  Nested lattice: halfX - nest*0.35, halfY - nest, yOffset nest, xOffset nest*0.35
  Guard: if halfX <= 4 || halfY <= 4, skip nested/rows
  Zigzag: valley → peak → valley → peak (moveTo then lineTo pairs)

navActive paint (_paintNavActive) — UNCHANGED in spirit:
  Horizontal linear gradient fade:
    primaryColor alpha 0.07 → 0.02 → 0.0  at stops 0.0, 0.55, 1.0
  Two round-cap zigzags, period 14, amplitude (height*0.28).clamp(4, 9)
  Echo path offset +5 y, amplitude * 0.7, alpha * 0.45

shouldRepaint: variant, strokeColor, primaryColor, patternOpacity

Used on:
  shopper landing body
  PDP body
  checkout body
  vendor content column
  vendor sidebar (light + backgroundColor surfaceLowest)

Vendor sidebar USED to pass patternOpacity: 0.07. That override was REMOVED
